四、資料庫與執行期資料安全警告

  • 安全警告：data/xiaoji.sqlite 是吉幣 SQLite 預設資料庫位置。雖然目前只看到 data/.gitkeep，但 bot 啟動並初始化吉幣資料庫後可能建立 SQLite 檔。
  • 安全警告：如果設定 COIN_DB_PATH，實際資料庫位置會改由該環境變數決定。搬移資料庫前必須先確認 .env 與部署環境的 COIN_DB_PATH。
  • 安全警告：src/data/*.json 是執行期資料，不應當成純原始碼隨意覆蓋。部署前要確認不會用空檔覆蓋正式資料。
  • 安全警告：正式環境更新前應備份 data/、src/data/ 與任何 COIN_DB_PATH 指向的檔案。
  • 安全警告：不要在 Discord 回覆、log 或文件中輸出完整 stack trace、token、API key、資料庫絕對路徑或使用者敏感資料。

五、PM2 與部署安全警告

  • 安全警告：PM2 使用 ecosystem.config.cjs，其中 script 是 src/index.js。如果移動入口檔，PM2 必須同步修改。
  • 安全警告：PM2 log 會寫入 logs/xiaoji-out.log 與 logs/xiaoji-error.log。log 不應提交到公開 repo。
  • 安全警告：部署前務必確認 .discloudignore、.koyebignore 或 release script 不會打包 .env、logs/、資料庫檔。
  • 安全警告：.release-upload/ 是部署產物副本，不是主要開發來源。不要在副本內修改功能後忘記同步回主專案。
  • 安全警告：如果使用 pm2 restart 或遠端部署，確認環境變數已更新，否則小吉可能仍使用舊 token、舊 guild id 或舊資料庫路徑。

六、讓小吉正確且流暢運作的檢查清單

檢查項目 建議做法 風險
環境變數 確認 .env 有 DISCORD_TOKEN、DISCORD_CLIENT_ID、DISCORD_GUILD_ID、BOT_OWNER_ID 等實際程式使用的名稱。 缺少必要變數會讓小吉無法啟動或無法部署 slash command。
依賴套件 使用 npm install 依 package-lock.json 安裝，不手動改 node_modules/。 依賴版本不同可能導致 Discord API、voice、sql.js 行為不同。
Slash command 部署 修改 command 後執行 npm run deploy。 未部署時 Discord 端看不到新指令或仍保留舊 schema。
資料備份 正式部署前備份 data/、src/data/、COIN_DB_PATH。 吉幣、投票、提醒、伺服器設定可能因覆蓋或刪除而遺失。
權限與安全 管理指令需維持 admin/owner 檢查；不要把 owner-only 指令註冊到不該暴露的 scope。 權限錯誤會讓一般成員使用管理、ban、清訊息、吉幣管理等高風險功能。
log 監控 本機用 console，正式環境用 npm run pm2:logs 查看錯誤。 長期不看 log 可能無法發現 command 失敗、資料庫寫入錯誤或 API quota 問題。
大型暫存檔 *-player-script.js 看似產物，但刪除前應先測試音樂功能。 若音樂功能間接依賴，刪除可能造成播放失敗。
部署副本 .release-upload/ 與 .release-upload.zip 應由 script 重新產生。 使用舊部署包可能把舊程式、舊設定或漏檔部署到正式環境。
